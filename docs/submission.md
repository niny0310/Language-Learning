4. loop / graph 流程（流程圖見 repo 的 docs/graph.png）
Wiki 階段（loop）：讀資料 → 寫證據卡與概念頁 → lint 腳本檢查 → 另開新對話的 AI 審查（最多 3 輪）→ 不通過就改回證據卡的原意。
簡報階段（graph）：檢索 Wiki 產生證據包 → 覆蓋率關卡（每頁要有 A 級證據，資料少於 3 篇就停）→ 大綱 → 我確認 → 逐頁寫稿（每頁小 loop：腳本檢查出處、比對數字，最多 2 輪）→ 忠實度關卡（新 AI 審查，最多 3 輪）→ 渲染 HTML（不准改字）→ 渲染檢查（溢出、測驗、文字是否被改）→ 交件。
重複執行的步驟：ingest＋lint、逐頁稿的小 loop、AI 審查。
需要檢查或重新生成的地方：錯在哪一關就退回哪一關。某頁說法比證據強，只退回那一頁；要用的證據不在證據包，退回檢索；排版 bug 退回渲染。
為什麼這樣設計：Wiki 每篇的處理方式都一樣，適合用 loop；簡報各階段的標準不同，用 graph 才能只重做出錯的那一關，不用整份重來。
